# Da tarefa à mudança revisável

GitHub Flow é um fluxo baseado em branches: crie uma branch para uma mudança, faça commits, publique o trabalho, abra uma pull request, discuta e revise a proposta, depois integre-a. A branch principal continua sendo a referência enquanto a mudança está em análise.

Uma issue pode registrar uma tarefa, erro, ideia ou pergunta. Uma issue bem escrita descreve o contexto, o resultado desejado e como verificar se o trabalho está pronto. Não transforme a issue em uma lista vaga de desejos.

Exemplo de sequência:

1. Abra uma issue: “Documentar como iniciar o projeto”.
2. Crie `docs/como-iniciar` a partir da branch principal atualizada.
3. Faça uma mudança pequena e commits claros.
4. Envie a branch e abra uma pull request vinculada à issue.
5. Revise, atualize conforme necessário e integre após aprovação.

### Prática

Escreva uma issue para melhorar o README de um projeto de estudo. Inclua problema, resultado esperado e dois critérios verificáveis. Crie uma branch cujo nome deixe clara a tarefa.
