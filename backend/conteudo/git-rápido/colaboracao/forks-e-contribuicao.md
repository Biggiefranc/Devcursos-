# Quando usar um fork

Em um repositório no qual você tem permissão de escrita, normalmente pode criar uma branch e abrir uma PR no mesmo repositório. Em projetos abertos nos quais você não tem essa permissão, um **fork** cria uma cópia do repositório sob sua conta. Você trabalha nessa cópia e propõe as mudanças ao projeto original por uma pull request.

Antes de contribuir, leia o README, as diretrizes `CONTRIBUTING.md` e o código de conduta, se existirem. Procure issues abertas, confirme que alguém não está fazendo a mesma tarefa e siga o escopo e as convenções do projeto. Uma contribuição pequena e bem descrita é mais fácil de avaliar.

Um fork não concede acesso ao repositório original. Ele permite que você publique sua cópia e proponha alterações; os mantenedores decidem se e quando integrá-las.

### Exercício de leitura

Escolha um projeto open source pequeno. Sem abrir uma PR, localize o README, as diretrizes de contribuição e uma issue marcada como adequada para iniciantes. Resuma o que o projeto espera de uma contribuição.
