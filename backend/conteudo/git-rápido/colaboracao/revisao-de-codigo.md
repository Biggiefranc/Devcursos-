# Revisão é uma conversa técnica

Uma revisão examina se a mudança atende ao objetivo, se é compreensível e se introduz riscos ou falhas. Comentários úteis apontam um trecho específico, explicam o impacto e sugerem uma pergunta ou caminho de melhoria. Separe problemas que bloqueiam a integração de sugestões opcionais.

Quem recebe comentários deve entender a observação, discutir dúvidas e enviar correções em novos commits na branch da PR. Depois, sinalize quais conversas foram resolvidas. No GitHub, o fluxo e as permissões de aprovação dependem das regras configuradas no repositório.

Antes do merge, confira o diff final, os checks disponíveis e a conversa. Os modos de integração oferecidos pelo GitHub podem produzir históricos diferentes; siga a convenção do projeto. Após o merge, a issue pode ser encerrada automaticamente quando a descrição usa a palavra-chave de fechamento suportada e aponta para ela.

### Prática em dupla ou individual

Troque a PR com outra pessoa e revise uma mudança de README. Registre um comentário que identifique uma dúvida real. Se estiver sozinho, faça uma pausa, leia o diff como alguém que não conhece a tarefa e liste uma melhoria concreta.
