# Desafio: uma mudança que outra pessoa consegue revisar

Escolha um projeto pequeno e seguro para compartilhar. Pode ser uma página simples, um programa de terminal ou um repositório de anotações técnicas. A visibilidade pode ser privada; você não precisa publicar informações pessoais.

## Entregáveis

1. Um repositório com `README.md`, `.gitignore` e instruções que outra pessoa consegue seguir.
2. Uma issue com problema, resultado esperado e critérios de conclusão.
3. Uma branch dedicada à issue, com pelo menos dois commits focados.
4. Uma pull request com título, objetivo, resumo e forma de verificar.
5. Uma revisão do diff; registre uma observação e responda a ela com uma melhoria ou justificativa.
6. Um merge seguindo a convenção do repositório, seguido de uma conferência do histórico.

Se trabalhar sozinho, faça a revisão em duas passagens: escreva a PR, afaste-se por alguns minutos e depois leia o diff como revisor. Anote uma melhoria encontrada e publique-a em outro commit na mesma branch.

## Rubrica de revisão

- **Repositório:** a apresentação e as instruções são suficientes para começar?
- **Histórico:** os commits representam etapas pequenas e explicáveis?
- **Segurança:** `.gitignore` cobre arquivos locais e não há credenciais no histórico?
- **Colaboração:** a PR explica motivo, escopo e verificação?
- **Integração:** o diff foi revisado e o merge pode ser identificado no histórico?

Registre a URL da PR ou, em repositório privado, guarde o link localmente. Não inclua tokens ou credenciais na entrega.

**Fonte de referência:** [Fluxo de Pull Requests do GitHub](https://docs.github.com/en/pull-requests/get-started/pull-request-quickstart)
